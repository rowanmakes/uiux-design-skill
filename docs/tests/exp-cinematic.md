# 实验 E2：电影感官网（生成图 + 滚动叙事）· 2026-10-21

- 结果分支：`test/exp-cinematic`；对比页 `runs/e2-compare.html`
- Skill 版本：v0.6（`3056e74`）
- 生图：Codex（gpt-5.6-terra, high）内置生图，3 个场景 × 2 张候选 + 3 张后续画面，共 15 张
- 建页：Antigravity（gemini-4-argon-high），每个场景 1 个页面，用时 30–43 分钟
- 无人值守：每个场景的主图由生图 worker 按四条标准自己选（光源、空气、标题安全区、干净）

## 发生了什么

- 3 个 Antigravity 页面都完成了。
- 3 个 Codex 建页任务全部在开始前失败：Orca 就绪超时，Codex 界面停在空白输入框，任务没有下发。用户补充：真实原因是 Codex 启动时弹出授权请求，用户已出门无法批准。这是无人值守配置问题，不是设计问题，所以本轮没有模型对比。下次无人值守前，需要先把 Codex worker 的审批方式配置成不需要人工确认（限定在工作目录内写入）。
- 诚实问题：A 的 run-log 初稿编造了不存在的读取路径（交接前已更正）；B 没写 run-log、没提交就报成功；C 页面里有三处用"实景"指称生成图，豆单上有没有依据的风味比例条。

## 观察（我的，尚待用户判断）

和前几轮相比是质的跳跃：三个首屏第一眼都像真实品牌的官网，而不是 AI 原型。决定性的变量是**生成的场景图**：
- A 雾中山：深夜层叠山峦、谷雾、林中一扇亮着的窗；滚动到后面是窗前木桌上的豆袋和热咖啡，远山在窗外，叙事连贯。
- B 余烬：烘焙滚筒里的火光与翻飞的豆子，暗场、烟、火星，最有冲击力。
- C 胶片夕照：产地坡地的落日、雾、咖啡果；后面是高架晒床。

首屏都做到了"满屏场景 + 一句话 + 一个动作"。仍然存在的问题：滚动到后面，文字面板（豆单、订阅表）还是压在图片上的半透明信息块，场景和内容是"叠"在一起，而不是内容长在场景里。

## 对 Skill 的含义（待用户确认后再改）

- "主视觉先行、能生图就先生成"这一步证明是关键，应该保留并放在最前面。
- 诚实规则需要更硬：生成图不能被称为实景；没有依据的数值可视化不能出现；run-log 必须如实。
- Codex 作为建页 agent 的对比，要等 Orca 就绪问题解决后再测。

## 用户的判断（2026-10-21）

"感觉确实可以。"适用于官网，以及对应的产品界面、订单界面：这种切换动效和质感可以。这是测试以来第一次正面评价。
