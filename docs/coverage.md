# 覆盖矩阵

目的：如实记录这个 Skill 在哪些场景有证据、哪些只是写了规则、哪些还没覆盖。"覆盖"只按测试证据算，写了文件不算。

更新：2026-10-21（v0.13）

## 证据等级

- **A 已验证：** 用户看过成品，评价可以。
- **B 测过未达标：** 跑过测试，结果不行或未交付。
- **C 写了规则未测：** 参考文件里有，但没跑过。
- **D 未覆盖：** 参考文件里基本没有。

## 已知的系统性风险

- 证据全部来自一个虚构品牌、一个建页模型（Antigravity）。
- 评判者只有用户一人，样本很小。
- 生成图质量依赖 Codex 的生图能力，换工具可能结果不同。

## 补覆盖的测试计划

原则：题材之间差得越远越好；每轮都是同一流程（生图 → 三个方向 → 用户挑 → 深化），用户只需判断"可以 / 不行 / 差在哪"。优先测用户真实要做的产品。

**下一批（按优先级）：**
1. 同品牌"首页 → 产品页 → 订单页"完整流程（验证 1.6 节的切换与质感）
2. 一个与咖啡差别很大的品牌官网（验证 1.7 节：能否一眼分出是两个品牌）
3. 高信任行业官网，例如医疗预约或理财（验证电影感是否应该退让）
4. 重跑工作台简报 07（v0.7 下能否在时限内交付并达标）
5. 手机 App 简报 06
6. 一个"首屏即行动"的工具型官网（验证 1.8 节的其他形式）

**回归集：** 每次 Skill 有较大改动后，重跑 3 个固定简报（咖啡官网、工作台 07、一个用户真实项目），确认没有改坏已经达标的部分。
