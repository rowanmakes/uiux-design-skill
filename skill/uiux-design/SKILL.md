# UI/UX 设计技能

## 三条核心信念

1. **界面是帮用户完成一个决定。** 先问"谁、在什么情境、要做什么决定"，再选布局、字体和色彩。
2. **品牌同时影响三件事：说什么、展示什么、如何行动。** 只有形容词（"专业、温暖"）的品牌无法指导实现，必须转成可观察的界面行为。
3. **规则是提醒，不是质量证明。** 功能通过、token 一致、检测零报错，都不等于设计优秀。最终要回到用户任务、品牌约束和真实渲染出的画面。

## 第 0 步：判断任务，决定工作量

先分类，再只做需要的步骤。小改动重走全流程是浪费，也会让输出变得平庸。

| 任务 | 走哪些步骤 |
| --- | --- |
| 新品牌站、显著改版 | 1 → 8 全流程 |
| 已有产品，某区块显得平 | 保持现有身份；1（简版）→ 4（仅该区块）→ 5 → 7 |
| 小修复（表单、状态、间距、文案） | 只做 5、7 中受影响的部分 |
| 只要评审 | 7 |

**输入不足时：** 完全没有主题（"帮我做个网站"）才问一个简短问题；其余情况写出一行假设直接开工，并在交付时说明。

**同时判断页面任务**，它决定表达强度（见下表）：了解并决定 / 操作 / 阅读 / 欣赏作品。

| 页面任务 | 用户此刻需要 | 设计重点 | 表达强度 |
| --- | --- | --- | --- |
| 了解并决定 | 理解价值、判断是否适合、行动 | 清楚主张、真实证据、视觉记忆点 | 高 |
| 操作 | 快速准确完成工作 | 稳定布局、可扫描信息、完整状态 | 低而稳 |
| 阅读 | 建立理解、定位、回查依据 | 标题层级、行长、目录、引用 | 中，节奏优先 |
| 欣赏作品 | 直接看到作品 | 作品主导，界面退后 | 界面低，作品高 |

同一品牌可以在不同页面用不同"音量"：身份稳定（语气、色彩角色、字体系谱、图标语言、素材原则），标题尺度、密度、动效随任务变化。

## 八步流程

每步写明"留下什么"和"何时进入下一步"。能在对话里说清的，不另建文件。

**1 · 确认事实。** 整理目标用户、主任务、替代方案（没有这个产品时用户怎么办）、真实差异与证据、已有身份、可用素材。把"事实 / 假设 / 缺失"分开写。影响方向的未知补足或标为待验证即可进入下一步；不要为一个设置页重做品牌战略。

**2 · 定义品牌行为。** 3–5 条原则，每条配"可观察的界面行为"和"不应推导出的做法"。例：可信 → 标明证据与来源，限制、费用、失败原因都找得到；不是把全站染蓝或编造客户 Logo。模板见 `references/brand-to-interface.md`。

**3 · 拆解参考。** 找 2–4 个与当前页面任务相关的参考（营销页不能证明登录后的工作流合理）。每个只记三件事：借什么、为什么有效、不借什么。能解释"为什么适合"才算通过，只喜欢颜色不算。

**4 · 探索方向。** 用同一份内容做 2–3 个差异明显的方向，差异要体现在构图、内容叙事、素材使用上，不只是换配色。每个方向给：首屏 + 一个关键内容段 + 窄屏示意。检验：删掉 Logo 还能认出产品吗？把名字换成竞争者，几乎不用改吗？（只用于发现问题，不是独特性的量化证明）

**5 · 实现代表页。** 选一个体现品牌的页面，一个能暴露使用问题的页面（长标题、多筛选、空数据、大量结果）。放入真实长文案、主操作和必要状态，宽窄屏都要成立。先做代表页，再批量扩展。

**6 · 提炼系统。** 只提取确实被复用的东西：语义颜色（一个主题来源、按用途命名）、字体层级、间距、组件与状态。其他页面能复用、无需逐页发明例外，才算提炼成功。过早标准化未成熟的设计是常见错误。

**7 · 双线评审。** 一条看任务与视觉表达，一条查操作、响应式、可访问性。必须修的缺陷与审美偏好分开记录。格式和证据规则见 `references/review-and-evidence.md`。

**8 · 验证与沉淀。** 有目标用户就让他们完成关键任务；没有就如实标为"专家走查"。记录修改理由和有效规则，为下次留一份可复用简报。证据足够支持当前交付即可停，不为追求评分无限打磨。

## 实现要点（落到 HTML 时）

- 颜色只有一个来源（CSS 变量或主题文件），按用途命名（`--text-muted`、`--surface-raised`），不在组件里写死色值。
- 字体层级先于装饰。常规阅读用稳定的正文字体，个性放在标题和关键时刻。
- 宽屏和窄屏都用真实内容检查，注意固定导航占位。
- 主动作按"触发 → 系统反馈 → 结果 → 下一步"设计，覆盖该流程实际需要的状态：正常、空、等待、错误、成功、取消/恢复。
- 键盘可操作、焦点可见、对话框焦点进入与返回、`prefers-reduced-motion` 处理、文字对比度达标。
- 当用户要辨认真实地点、商品、人物时，用能识别对象的真实图片；装饰性插画帮不上忙。
- 按钮文字对应实际结果；视觉隐喻不能改变业务含义（票券形状的推荐卡不应让人以为已领到票）。

## 默认视觉方向

用户或品牌没有指定风格时，默认方向是"留白、干净、简约、大气、干练"的高级感。它恰好也是模型最容易滑进去的默认外观，所以只写这几个词不够：动手前先读 `references/taste.md`，按其中的参数、骨架、素材和中文规则执行，交付前过一遍它的自检清单。

## 风格建议是提醒，不是法律

"避免默认字体、卡片堆叠、紫色渐变"这类规则能帮你警觉模板味，但不能升级成全局禁令：Wise 和 Linear 都有理由继续用 Inter。判断标准始终是：这个选择是否帮用户更容易理解、比较和行动，是否符合品牌约束。

两种取向要按场景选，不要同时写成硬规则：
- **探索新品牌：** 大胆方向、记忆点、独特字体，用来扩展候选。
- **给具体产品定稿：** 以用户任务、内容可信度和既有品牌约束取舍，克制优先。

## 诚实规则

- 不编造客户、评价、数据、业务承诺；假想或样例内容明确标记。
- 只声明实际做过的检查。截图证明可见状态；键盘、动画、失败恢复需要实际操作才能说验证过。
- 没有目标用户参与，写"专家走查"，不写"已通过用户测试"。
- 如果裁剪了某个外部方法的流程，标为"适配版"，不说完整执行了原方法。
- 保存证据时标明版本、页面、视口、状态，不拿旧截图说明新版本。

## 交付时怎么说

结尾简短交代四件事：做了什么与关键取舍；你的假设；实际验证了什么；还没验证的与下一步建议。

## 何时读参考文件

- 任何新视觉设计或视觉改版（官网、落地页、作品集、界面重做）→ `references/taste.md`
- 需要把品牌词转成界面动作、选表达强度、写状态文案 → `references/brand-to-interface.md`
- 需要可用性原则、UX 定律的正确用法、可访问性清单 → `references/ux-foundations.md`
- 做评审、写问题卡、判断证据够不够 → `references/review-and-evidence.md`
- 想借鉴或比较外部设计技能 → `references/skill-landscape.md`

本技能是主方法。动效细节、无障碍专项、性能排查等，只在问题出现时再补一个对应的专项技能，不同时加载多套互相冲突的风格规则。
