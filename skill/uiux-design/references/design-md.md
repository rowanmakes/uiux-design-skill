# DESIGN.md：把选定的方向写成规范

在用户挑定方向之后、深化页面之前写。它是后续所有页面（官网、产品页、订单页）和以后每次会话都要遵守的规范，也是 agent 之间交接设计的方式。

**为什么在挑方向之后写，而不是一开始写：** 测试中，一开始就把几个参考综合成一份规范，结果往往是参考的平均值，平平无奇；先做出三个看得见的首屏、让用户挑，再把选中的那个写成规范，才不会过早锁死。用户已经明确给了风格时，可以提前写。

**写规范时不改代码。** 写完先给用户看，确认后再按它深化页面。

## 不从空白开始：用现成的 DESIGN.md 当种子

awesome-design-md 仓库（https://github.com/VoltAgent/awesome-design-md，84 份）和它的网站 getdesign.md（550 多份）收录了知名网站的 DESIGN.md。从一份接近的开始，比从空白开始精度高得多。但测试和调研都显示，"照一个品牌改一改"最容易变成那个品牌的翻版，所以有三条底线：

**1. 三个方向用三份不同的种子。** 只挑一份最近的，所有方向都会长得像它。

| 种子 | 作用 | 举例（咖啡订阅官网） |
| --- | --- | --- |
| 同类或结构相近 | 用户习惯的结构、信息顺序 | starbucks（仓库里有），或其他消费品牌 |
| 用户喜欢的参考 | 用户要的精度和气质 | apple、linear.app、x.ai、cursor |
| 跨品类 | 新鲜感 | oura、airbnb、nike 这类和咖啡不相干但气质可借的 |

**2. "最近"按页面任务和密度算，不按行业名算。** 一个品牌官网和一个开发者文档站，即使同属科技行业，也不该互为种子。仓库大部分是科技和开发者产品，非科技题材往往找不到同行，这时用"结构相近"代替"同行业"。

**3. 改造要真的改，并写下改了什么。**
- 品牌资产全部换成我们的：Logo、品牌色、字体组合、文案语气不能沿用种子品牌的。
- 主视觉用我们自己的（第 3 步生成的场景），不用种子的图片风格。
- `taste.md` 1.7 节的六个外观轴（时间与光、明暗、空气、镜头、色彩、节奏）至少改三个。
- 在 DESIGN.md 末尾写"种子与改造"：用了哪份种子、保留了什么（例如间距刻度、字号层级的比例）、改了什么、为什么。
- 检验：把成品和种子品牌的官网并排看，别人能不能一眼分出是两个品牌。分不出就是撞脸，重改。

## 模板

```markdown
# DESIGN.md · <项目名>

## 北极星与气质
- 北极星：一句话，这个页面要让人第一眼感受到什么 / 帮用户完成什么。
- 气质：一句话加五个刻度，能量（安静 ↔ 喧闹）、完成度（粗粝 ↔ 精致）、密度（疏 ↔ 密）、分量（轻 ↔ 重）、严肃度（活泼 ↔ 庄重），各写取哪一端、依据是什么。

## 参考与取舍
| 参考 | 位置（基线 / 天花板 / 新鲜感 / 氛围） | 借什么（具体关系） | 不借什么 |
每条"借"写成可执行的关系，例如"光只从一个方向来，其余全暗"，不写"干净高级"。

## 这个产品才有的东西
哪些素材、场景、术语、细节只属于这个产品，换成竞品就不成立。

## 主视觉与素材
- 主角是什么（场景 / 产品 / 用户内容 / 字）
- 生成图的风格与提示词要点（时间、光、空气、镜头、色调）；后续画面如何保持一致
- 没有图时的替代办法

## 色彩
按用途命名的变量与色值，至少：底色、表面、主文字、次文字、强调色、边线、状态色。每个颜色写一句来源。

## 字体
展示、正文、数字、等宽各用什么；字号层级（比例与具体值）；行高、字距；中文规则（见 taste.md 第 6 节）。

## 留白与布局
留白程度（宽松 / 适中 / 紧凑，以及区块之间的具体距离）；间距刻度；组内 / 组间 / 区块之间的距离；内容宽度；首屏骨架；窄屏怎么重排。

## 组件与状态
按钮、输入、卡片、导航、标签共用的一套形状和手感（圆角、描边、按下的变化）；每个组件需要的状态。

## 动效
动效程度，选一档：1 只有悬停与按下反馈；2 加上弹层与状态过渡；3 加上首次出场与页面切换；4 加上环境动效（雾、光、粒子）；5 加上滚动驱动的叙事。官网通常 4–5，产品页 3–4，订单页 2–3，工作台 1–2。
手感（动作 + 实物，例如"咔嗒：磁铁吸合"）；环境动效（雾、光、粒子）的速度；滚动叙事的分镜；页面之间的切换方式；减少动态效果时怎么处理。

## 页面结构与叙事
首页、产品页、订单页各自的结构，以及它们之间如何保持同一个世界又降低音量。

## 不适合我们的设计
这个方向主动拒绝的做法，包括从种子和参考里看到、但不适合我们的部分（例如左右分栏、紫色渐变、到处贴"样例"标签、种子品牌标志性的配色）。

## 验收
做完怎么判断成功：换名字测试、模糊测试、和参考板并排看、用户看过的反应。
```

## 给用户确认时的清单

用户看方向截图时，请他确认三件事，并对照下面的清单自查一遍：

**1. 整体感觉对吗？** 和北极星、气质写的一致吗？

**2. 有没有漏掉用户最喜欢的东西？**（用户确认过的喜好，2026-10-21）
- 官网：有来源的光、空气感、像一个场景（电影感）；首屏只有一句话；页面之间切换连贯、有质感。
- 工作台：极客式的精确、快、键盘优先、系统是活的。
- 共同：留白、干净、简约、大气、干练；一处做到极致，其余安静。

**3. 有没有加入用户不喜欢的元素？**（用户否定过的）
- 暖米色纸底 + 衬线标题 + 陶土点缀，以及各种千篇一律的"安静高级"
- 首屏塞满信息的控制台式布局
- 到处贴的"样例""占位"标签
- 只有字、没有场景的冷感极简（xAI 式的"缺席"）
- 个性强但不精致的怪趣味（如 Teenage Engineering 式的巨物感）

用户每次新的"喜欢 / 不喜欢"都补进这份清单和 `taste.md`。

## 写的时候注意

- **具体到能照着做。** 每一节都要写到数值或明确的关系；只写形容词的规范等于没写。
- **引用来源，不复制网页。** 从参考里借的是关系，不是某个品牌的 Logo、配色组合、字体组合和版式整体。
- **规范跟着项目走。** 放在项目根目录；之后的页面先读它；有改动就更新它，并在末尾记一行改动日期和原因。
- **交付时把外观记进账本：** `python3 $SKILL/scripts/design_lint.py ledger add <最终页面> --project <名字> --note "形式、主光、空气、镜头"`，用于下一个项目避开（见 `taste.md` 1.7 节）。
