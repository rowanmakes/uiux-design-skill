# DESIGN.md：把选定的方向写成规范

在用户挑定方向之后、深化页面之前写。它是后续所有页面（官网、产品页、订单页）和以后每次会话都要遵守的规范，也是 agent 之间交接设计的方式。

**为什么在挑方向之后写，而不是一开始写：** 测试中，一开始就把几个参考综合成一份规范，结果往往是参考的平均值，平平无奇；先做出三个看得见的首屏、让用户挑，再把选中的那个写成规范，才不会过早锁死。用户已经明确给了风格时，可以提前写。

**写规范时不改代码。** 写完先给用户看，确认后再按它深化页面。

## 模板

```markdown
# DESIGN.md · <项目名>

## 北极星
一句话：这个页面要让人第一眼感受到什么 / 帮用户完成什么。

## 参考与取舍
| 参考 | 位置（基线 / 天花板 / 新鲜感 / 氛围） | 借什么（具体关系） | 不借什么 |
每条"借"写成可执行的关系，例如"光只从一个方向来，其余全暗"，不写"干净高级"。

## 这个产品才有的东西
哪些素材、场景、术语、细节只属于这个产品，换成竞品就不成立。

## 主视觉与素材
- 主角是什么（场景 / 产品 / 用户内容 / 字）
- 生成图的风格与提示词要点（时间、光、空气、镜头、色调）；后续画面如何保持一致
- 没有图时的替代办法

## 色彩
按用途命名的变量与色值，至少：底色、表面、主文字、次文字、强调色、边线、状态色。每个颜色写一句来源。

## 字体
展示、正文、数字、等宽各用什么；字号层级（比例与具体值）；行高、字距；中文规则（见 taste.md 第 7 节）。

## 留白与布局
间距刻度；组内 / 组间 / 区块之间的距离；内容宽度；首屏骨架；窄屏怎么重排。

## 组件与状态
按钮、输入、卡片、导航、标签共用的一套形状和手感（圆角、描边、按下的变化）；每个组件需要的状态。

## 动效
手感（动作 + 实物，例如"咔嗒：磁铁吸合"）；环境动效（雾、光、粒子）的速度；滚动叙事的分镜；页面之间的切换方式；减少动态效果时怎么处理。

## 页面结构与叙事
首页、产品页、订单页各自的结构，以及它们之间如何保持同一个世界又降低音量。

## 不做什么
这个方向主动拒绝的常见做法（例如左右分栏、紫色渐变、到处贴"样例"标签）。

## 验收
做完怎么判断成功：换名字测试、模糊测试、和参考板并排看、用户看过的反应。
```

## 写的时候注意

- **具体到能照着做。** 每一节都要写到数值或明确的关系；只写形容词的规范等于没写。
- **引用来源，不复制网页。** 从参考里借的是关系，不是某个品牌的 Logo、配色组合、字体组合和版式整体。
- **规范跟着项目走。** 放在项目根目录；之后的页面先读它；有改动就更新它，并在末尾记一行改动日期和原因。
- **交付时把外观记进 `appearance-ledger.md`**（形式、明暗、主光、空气、主色、镜头、字体），用于下一个项目避开。
