## 1. 品味画像

用户的原话：**留白、干净、简约、大气、干练。**

喜欢：Linear（极客精确）、苹果（简约克制）、Spaceship（动效）、Cursor 官网、Grok（高级）、Dishoom、Awwwards 上的获奖作品。
无感：Stripe Press（动效好但"感受不出什么"）、The Pudding、Teenage Engineering（"巨物感，不高级"）。

由此得出的判断标准：**第一眼就感到高级，干净、克制、有分量。** 需要慢慢读才能体会的概念深度、个性很强但不精致的怪趣味，都是加分项，不是核心。

**按页面类型分成两套（用户确认，2026-10-21）：**
- **官网（用户来看）：电影感。** 在 6 种氛围的试样板里，用户选了"雾中山（深夜远山、淡月、雾）""余烬（暗场里的烘焙火光与火星）""胶片（上下黑边、暗绿到琥珀的胶片色调与颗粒）"；没选"白昼（白底苹果式）""留白（水墨竖排）""缺席（炭黑底只有描边巨字，xAI 式）"。区分点不是"暗"也不是"极简"：被选中的都是**有光源、有空气、像一个场景**的画面；落选的要么是亮的，要么只有字、没有场景，是冷的。
- **工作台（用户来用）：极客感。** 参照 Linear、Raycast 的客户端：精确、快、键盘优先、系统是活的。

**实验 E2 验证（用户确认，2026-10-21）：** 用生成的场景图加滚动叙事做出的三个电影感首页（雾中山、余烬、胶片夕照），用户评价"确实可以"。用户还确认：同一品牌的**产品页、订单页**也要这种切换动效和质感，不只是首页。

前几轮测试里，浅色纸底那一路用户全部否定；深色的"风味控制台"虽然暗，但它是信息面板而不是场景，同样没打动用户。

## 1.5 官网：电影感的配方

| 成分 | 做法 | 起点参数 |
| --- | --- | --- |
| **暗场** | 不是纯黑，带色温的深色（深蓝夜、暖黑、暗绿），整体是一个连续的空间而不是一块平底 | 明度 4–15%；从上到下或由边缘到中心有缓慢的明暗渐变 |
| **有来源的光** | 画面里有一个说得出来源的光：月亮、炉火、窗光、夕阳。光的方向全页一致，文字和物体受它影响 | 一个主光源；亮部只占画面一小块，周围是暗 |
| **空气介质** | 光穿过的东西：雾、烟、蒸汽、火星、尘埃、胶片颗粒。让屏幕有深度 | 颗粒不透明度 0.08–0.25；雾用大面积模糊；粒子稀疏 |
| **场景感** | 一个有地点和时间的时刻，来自题材本身（产地的山、烘焙间的深夜、收获的傍晚），不是抽象装饰 | 说得出"这是哪里、几点、什么天气" |
| **缓慢的自然动效** | 雾在移、光在呼吸、火星在升、颗粒在抖；一直在动但很慢，不抢注意力 | 雾 30–60 秒一个来回，光呼吸 6–10 秒，粒子 8–14 秒；尊重"减少动态效果" |
| **一句话** | 首屏只有一句话和一个动作，字号克制，让场景说话 | 价格、清单、卡片全部放到首屏以下 |
| **滚动叙事** | 往下滑时场景推进（镜头拉近、光线变化、从山到炉到豆袋），内容在场景里出现，而不是切换到一屏屏卡片 | 至少一段由滚动驱动的叙事 |

**画面质量决定上限。** 用代码画的雾和山只能做到"好一点"（用户原话）。电影感要成立，主视觉最好是生成图或真实摄影：先生成场景候选给用户挑，再在图片上叠加代码做的雾、光、颗粒和动效。

## 1.6 电影感延伸到产品页与订单页

产品页和订单页是官网的一部分，用户来这里是为了看清、选好、付款，所以质感保留，音量降低：

| 页面 | 保留什么 | 调低什么 |
| --- | --- | --- |
| 产品页 | 同一套暗场、光源方向、颗粒和字体；产品画面延续首页的场景（同一个烘焙间、同一扇窗） | 环境动效更少、更慢；规格、价格、风味要清楚易比较，不压在花哨的半透明面板上 |
| 订单页 / 结账 | 背景的场景和色调，让用户感觉仍在同一个地方 | 表单区域用实底、高对比，不叠雾和粒子；完整性按 `interaction.md` 第 3 节的结账清单 |

**页面之间的切换是质感的一部分：**
- 从首页点进产品：被点的豆袋或画面放大成产品页的主图（共享元素过渡），场景不断开。
- 从产品进订单：场景缓慢变暗、退到背景，表单从下方或侧边出现，像镜头从远景拉到桌面。
- 返回时是逆过程，并回到原来的滚动位置。
- 切换控制在 350–600ms；开启"减少动态效果"时直接切换。网页可用浏览器的视图过渡（View Transitions）或成熟动效库实现。

## 1.7 电影感是方法，不是一张皮

用户提醒（2026-10-21）：如果所有官网和产品界面都是这一种样子，就没有特色和区别了。E2 的三个页面其实已经出现苗头：都是暗场、暖琥珀色的光、雾。照这样下去，"暗场 + 琥珀光 + 雾"会变成新的默认外观，和之前的"暖纸色 + 衬线"一样千篇一律。

**固定的是方法，不是外观：**
- 固定：画面主角是来自这个产品自己世界的一个场景；有一个说得出来源的光；有空气感；生图先行；滚动叙事；页面之间切换连贯；首屏克制。
- 不固定：明暗、颜色、时间、天气、镜头、字体、动效速度，全部从产品本身推出来。

**每个项目沿这些轴重新选：**

| 轴 | 可选范围（举例，不止这些） |
| --- | --- |
| 时间与光 | 黎明的冷光、正午的硬光、阴天的散射光、黄昏逆光、深夜的单一光源、霓虹、室内窗光 |
| 明暗 | 低调暗场，也可以是高调明亮的电影感（晨雾里的白、阳光下的海、雪地） |
| 空气 | 雾、雨、尘、蒸汽、雪、水下、热浪，或几乎透明的干净空气 |
| 镜头 | 大远景、俯拍、微距特写、平视的人眼高度、长焦压缩 |
| 色彩 | 从产品的材料、产地、文化里取（茶的青、海的蓝、钢的冷灰、纸的白），不默认琥珀 |
| 节奏 | 缓慢沉浸，也可以利落明快（运动、科技硬件） |

**判断标准：** 把两个不同品牌的页面放在一起，它们应该一眼能分出是两个品牌，只有"做得都很好"这一点相同。

**外观账本（防止跨项目趋同）：**
- 用 `$SKILL/scripts/design_lint.py` 的账本，它自动记录底色、主色板、字体和版式骨架，存在本机 `~/.huashu-design/ledger.jsonl`（可用环境变量 `HUASHU_DESIGN_HOME` 改位置），跨项目共用。
- 每次交付后：`python3 $SKILL/scripts/design_lint.py ledger add <最终页面> --project <名字> --note "形式、主光、空气、镜头"`（脚本量不出来的几个轴写进 note）。
- 新项目开工前：`python3 $SKILL/scripts/design_lint.py ledger` 看最近交付过的样子；方向做出来后 `python3 $SKILL/scripts/design_lint.py ledger check <方向页面…>`，撞了就换。六个轴里至少三个要和最近的项目不同，用户或品牌明确要求某种外观时除外。
- 用户自己的产品之间（例如官网和它的产品页）应当一致；要拉开的是不同产品、不同品牌之间。

## 1.8 形式的审美疲劳

外观可以换，但"满屏场景图 + 一句话 + 滚动叙事"这个**形式**本身也会被用烂，就像当年的视差滚动、后来到处都是的苹果式滚动展示。没有任何规则能永久避免疲劳，能做的是四件事：

**1. 形式必须由内容决定。** 滚动叙事只在内容本身就是一段旅程时才用（咖啡：产地 → 烘焙 → 杯中，这是真实的过程）。检验：去掉这个形式，信息是更清楚还是更糊？更清楚，就不该用。

**2. 有一套形式可选，不只一种：**

| 形式 | 适合 | 例子 |
| --- | --- | --- |
| 电影式滚动叙事 | 产品背后有真实的过程或场景 | 产地到杯中、一件手工品的制作 |
| 首屏即行动 | 用户来就是为了做一件事 | 域名搜索、生成、预约（Spaceship、Grok 的做法） |
| 单一物件 | 产品本身就是主角，可以转、拆、看细节 | 硬件、包、一袋豆子 |
| 编辑刊物 | 内容多、值得读 | 品牌故事、季刊、长文 |
| 索引与档案 | 作品或商品多，用户要浏览比较 | 作品集、产品目录 |
| 活的数据或系统 | 产品的价值在实时变化里 | 工具状态、库存、正在烘焙的批次 |

一个品牌可以在不同页面用不同形式（首页叙事、目录用索引、结账用最直接的流程）。

**3. 控制剂量。** 疲劳多半来自过量：每个区块都视差、每次滚动都有特效。全站只在一两处用最强的形式，其余安静、好用。

**4. 尊重回头客。** 第一次来可以看完整的叙事；第二次来的人是来办事的：
- 叙事不能挡住内容，随时能直接跳到产品和订单。
- 回访时（可用本地存储记住）缩短或跳过开场。
- 订单、结账流程永远不等动画。

外观账本也记录形式：新项目开工前，除了外观的六个轴，也看看最近几个项目是不是都用了同一种形式。

## 1.9 滚动叙事怎么做

E2 留下的问题：往下滑时，豆单和订阅表是压在场景图上的半透明面板，内容和场景"叠"在一起，而不是长在场景里。下面这些做法用来解决它。

**结构**
- **一个场景 = 一段固定的舞台。** 舞台在 1–4 屏的滚动距离里保持不动，滚动推进画面；每屏大约讲一个节拍，没有新东西可看就缩短，不要拖。
- **全页 2–3 个场景，中间夹安静的区块**（一段文字、一个清单、一张静图），每个场景才落得住；两个场景紧挨着会变成一段很长的过山车。
- **主角从产品里找**，在滚动里走完它自己的过程（产地 → 烘焙 → 杯中）；找不到就用简单的转场，不用通用的漂浮几何。
- **每一段结束要交接给下一段：** 主视觉缩到下一节的位置、让出一条路，而不是固定结束后整块被推走。

**文字**
- **停下来再说话。** 每个镜头留一段静止，文字在静止时出现；边动边读很累。
- **屏幕上一次只有一句话，4–12 个字。** 价格、规格、清单放在场景之间的安静区块里，或场景结束后的静止画面里，不做成压在动态画面上的面板。
- **文字下面要有安静的区域，** 或一层纯色遮罩；不在画面细节最多的地方压字。

**画面**
- **同一个场景里的图是一家人：** 同样的光、同样的色调、同类的主体（生图时用同一组提示词要点生成后续画面）。
- 视差只在画面本来就有前后层次时用；正文、按钮和表单不做视差。

**体验**
- **倒着滚也成立：** 每一帧只由滚动位置决定，往回滚自然倒放，刷新或跳到中间也是对的画面。不接管用户的滚动。
- 长段落前给一个跳过入口；常来的人能直接到产品和订单（1.8 节）。
- **减少动态效果、脚本失败、部分手机上看到的静态版本也要设计好：** 把每个静止画面按顺序排成普通区块，内容一样不少。
- 网页实现可用 GSAP 的 ScrollTrigger（`scrub` 做滚动驱动、`pin` 固定舞台），只动变换、透明度和裁切；项目有自己的技术栈就用它的方式。

**检查：** 从头滚到底再滚回来各看一遍录屏；跳到中段刷新看画面是否正确；看每个静止点的文字能不能读完、有没有东西从文字上划过。

来源：oil-ui `references/scroll-narrative.md`（`7002e1a`）、taste-skill `references/scenes.md`（`6010f91`）。

## 2. 最大的风险：安静高级正是模型的默认

三个独立的设计技能都记录了同一个现象：不加约束时，模型会滑向几种固定外观。

- 暖奶油底 + 高反差衬线标题 + 陶土或黄铜色点缀
- 近黑底 + 一个荧光绿或朱红强调色
- 细线报纸风：发丝线、零圆角、密集分栏
- 米色卡片 + 柔和阴影 + 大留白（oil-ui 称之为"被磨回模型默认的安静高级"）

这些外观本身不丑，问题是它们与题材无关地出现，所以一看就是 AI 做的。

**模板装饰**（生成时就避开，`design_lint.py check` 会再查一遍）：每个标题上方一行全大写小标签、"A · B · C" 中点连接、按钮尾巴的"→"、标题里只给一个词换色、不是序列却编号 01 / 02 / 03、紫色渐变、emoji 当图标、左侧彩条圆角卡片、三列一模一样的"图标 + 标题 + 一句话"特性卡。

**判别一句话：** 换一个同类品牌提同样的需求，你会给出同样的方案吗？会，就是条件反射，不是设计决定。

## 3. 从参考网站借关系，不借外观

借的是参考网站某个决定背后的关系，用当前产品的内容重新长出来；不复制颜色、字体、Logo 和版式。用户喜欢的几个网站各借什么，记在仓库的 `library/用户的品味参考.md`；找参考的方法见 `research.md`。

## 4. 安静但不平庸：力气花在哪

安静高级要成立，必须有真实的决定撑着，而不是靠空。力气集中花在下面几处，其余全部安静。

**1. 骨架。** 写文案之前先定首屏结构。左右分栏（左边标题说明按钮，右边一张图）是模型最顽固的默认，一轮最多用一次。其他选择：

| 骨架 | 首屏样子 |
| --- | --- |
| 居中单一物件 | 一个物件或一句话居中，四周大面积空白 |
| 满版图像压字 | 一张图占满首屏，标题压在安全区 |
| 画面即界面 | 首屏就是产品界面或实物本身 |
| 满版文字 | 字大到占满首屏、跨出边缘或被裁切 |
| 通栏上下堆叠 | 通栏大标题横跨整个宽度，下面紧接内容 |
| 纵排或斜向 | 竖排、斜切，打破从左到右的阅读 |

**调性决定音量，骨架决定结构。** 安静的产品一样可以把一句话放在空白首屏正中，不需要退回左右分栏。

**2. 一个主角。** 每屏只有一个元素最突出。把画面模糊 8px，应该只剩一个块面最醒目；相邻层级至少在一个维度上（大小、字重、对比、面积）差 1.5 倍。

**3. 一处记忆点。** 全页只在一两处集中发力：一个关键动作的反馈、一个让人意外的尺度、首屏的一次出场。它要说得出来自这个产品的什么。

## 5. 素材不足时：高级的空 vs 寒酸的空

苹果和 Grok 的留白有分量，是因为留白中间放的是顶级素材或极端的尺度。同样的留白，中间只放一行普通标题和三张卡片，就是寒酸的空。

**检验：** 留白里放的东西，单独拿出来值不值得被这么多空间围着？不值得，要么换素材，要么收紧留白。

没有好照片时，按顺序考虑：

1. **真实的产品画面或内容：** 界面截图、作品、实物照片。
2. **字即图像：** 巨字、裁切、竖排。字本身成为画面，而不是"标题 + 正文"的默认排法。
3. **数据即图像：** 把内容里的数字画成量（长度、面积、个数），而不是三个大数字卡片。
4. **克制的程序化材质：** 细腻的噪点、光影、几何，只在和题材有关时用。
5. **能生图时：** 先为每个方向出一张主视觉探针图，选定后再生成正式素材。
6. **都没有：** 诚实占位，并在交付时说明缺什么。不用通用插画和"灵感图"凑数。

**真图诚实性测试：** 去掉这张图，信息有没有损失？没有，它就是装饰，不加。

## 6. 中文规则（覆盖西文参数）

苹果、Linear 那套"大标题负字距、行高 1.05"是为西文设计的，中文界面以下面为准：

- **字距：** 正文 0 至 0.05em，标题 0，巨字最多 -0.02em。汉字是满格方块，套西文负字距会笔画相撞。
- **行高：** 巨字 1.1–1.25，多行标题 1.2–1.4，正文 1.6–1.8；正文每行 22–38 字。
- **字体：** 一页最多两个中文字体家族；`font-family` 西文字体在前、中文在后；表格数字加 `tabular-nums`。
- **强调：** 中文没有斜体，用字重、颜色或着重号，全局加 `font-synthesis: none`。
- **断行：** 标题用 `text-wrap: balance`；行尾孤零零一两个字算缺陷；"38 秒"这类数字加单位不拆开。

## 7. 动效：有含义才动

用户喜欢的动效（Spaceship、苹果）都在讲故事。每一个动画都要能用一句话回答"它传达了什么"：层级、顺序、反馈还是状态变化。答不上来就删。

**用户的原则（2026-10-21）：动效要么帮用户理解页面，要么突出真正重要的内容；不需要所有区块都动起来，宁可少用。** 一页里通常只有 1–3 处值得动，程度按 DESIGN.md 的动效档位。始终尊重"减少动态效果"；只过渡 transform、opacity 等，不写 `transition: all`。

**动效参考：Magic UI**（https://github.com/magicuidesign/magicui，网站 magicui.design，`efe76fc` 时有 75 个组件）。**只把它当参考，看动效该是什么样子；不直接安装使用。** 实现按项目实际的技术栈来：网页用项目已有的方式（CSS、Web Animations、项目已有的动效库），Flutter、React Native、Electron、Tauri 各用各自的动画能力。在 DESIGN.md 的动效一节写明"参考了 Magic UI 的哪个效果、在我们的技术栈里怎么实现"。按用途挑参考：

| 用途 | 适合的组件（举例） |
| --- | --- |
| 帮用户理解过程或关系 | animated-beam（东西之间如何流动）、animated-list（一连串事件）、terminal / typing-animation（展示一个真实过程）、arc-timeline、file-tree、code-comparison |
| 帮用户理解变化 | number-ticker（数值变化）、animated-circular-progress-bar、scroll-progress |
| 引导阅读顺序 | blur-fade、text-reveal、box-reveal（标题先到，正文跟上，只播一次） |
| 突出唯一重要的东西 | highlighter（一句关键话）、border-beam / shine-border（只给一个关键卡片或主操作） |
| 展示产品本身 | safari、iphone-15-pro 设备框、hero-video-dialog |

**最容易变成 AI 模板味、要慎用的：** aurora-text、animated-gradient-text、shimmer / rainbow / shiny 按钮、meteors、particles、sparkles-text、retro-grid、warp-background、globe、icon-cloud、orbiting-circles、confetti、cool-mode、marquee 的 Logo 滚动墙、neon-gradient-card、自定义光标。它们本身不坏，但到处都是；只有在内容真的需要、而且全站只用一次时才用。

## 8. 交付前自检

模板装饰、默认外观家族、三个方向撞没撞、字号与对比度，交给 `$SKILL/scripts/design_lint.py`（`SKILL.md` 第 4、8 步）。下面是脚本量不出来、要看画面判断的：

- [ ] **换名字测试：** 把产品名换成竞争者，页面几乎不用改吗？是就重做。
- [ ] **模糊测试：** 模糊 8px 后，每屏只剩一个主角吗？
- [ ] **空的检验：** 每片留白中间放的东西撑得住吗？
- [ ] **过头检验：** 去掉那个最大胆的手法，信息更清楚了吗？清楚了就是过头。
- [ ] **中文检查：** 没有负字距、行高够、没有孤字、没有假斜体？
- [ ] **动效检查：** 每个动画都能说出它帮用户理解了什么、突出了什么吗？
- [ ] **滚动检查：** 文字在静止时出现、一屏一句话、往回滚也成立吗？（1.9 节）
