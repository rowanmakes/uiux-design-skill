# 先问清楚，再找参考

这是新设计开工前的两步。目的有两个：不在错误的方向上投入；遇到没专门写过规则的行业，也能当场学到这个品类该怎么做。Skill 的覆盖范围靠这一步扩展，而不是靠为每个行业预先写规则。

## 1. 先问清楚

**一轮，最多 3 个问题。** 只问会改变方向、又推断不出来的事；能从简报、现有页面、素材里推出来的，自己写成假设。

问题从这里挑：
1. **谁来用，来做什么？** 第一次来的人想知道什么，常来的人要做什么。
2. **有没有"就要那种感觉"的参考？** 网站、App、截图都行，也问"不要像什么"。
3. **有哪些真实素材？** Logo、品牌色、字体、产品图；没有的话，能不能用生成图。
4. **必须保留什么？** 现有品牌、页面结构、技术栈。
5. **交付到哪一步？** 首屏方向、完整页面，还是可运行的界面。

同时请用户把手上的参考一次发全。

**说不清的感觉，用看的代替问的。** 用户常常描述不出想要的氛围（"好像又不是那种"），这时继续追问没用。下一步做出参考板，让他指着说"这个对，这个不对"，比任何问题都快。

**没人能问时**（无人值守、用户说"你看着办"）：不问，把假设写在开头，继续做。

## 2. 找同类产品

### 先把品类说准

不是"咖啡网站"，而是"精品咖啡豆订阅制工作室的品牌官网"：**产品是什么 + 给谁用 + 怎么卖 + 这是哪种页面**。品类说得越准，找到的参考越有用。再列出 1–2 个相邻品类（例如茶叶订阅、精品巧克力），后面用来找新鲜感。

### 去哪里找

**先看用户的参考库和用户给的参考。** 用户看过、说过好的，优先级最高（见下文"参考库"）。

**再按要找的东西去对应的地方（用户常用的来源，2026-10-21）：**

| 要找什么 | 首选 | 补充 |
| --- | --- | --- |
| 个人站、作品集 | Minimal Gallery | Awwwards 的作品集分类 |
| 落地页、官网 | Land-book | Awwwards（可按行业分类）、Godly、SiteInspire |
| 产品界面、完整操作流程 | Mobbin（部分需要登录或付费） | Refero、Page Flows；App 看 Apple Design Awards |
| 某个品牌的设计系统细节：字号层级、间距、颜色角色、组件 | getdesign.md（用户最常用） | |
| 以上都没有 | Pinterest | |

**getdesign.md 怎么用：** 它收录了 550 多个知名网站的 DESIGN.md（颜色、字体、间距、组件及理由），单个品牌的地址形如 `https://getdesign.md/stripe/design-md`，是文字，agent 读起来很方便。用它学"顶尖品牌把细节做到什么精度"，借关系不借外观：
- 不要把某个品牌的 DESIGN.md 整个套进项目，那就是撞脸。
- 它收录的大多是科技品牌，只拿它当参考会把别的题材也拉成科技外观（测试中出现过）。
- 它是对网站的文字分析，看不到实际画面、氛围和动效，也可能落后于网站改版；用之前还是要打开真站截图看一眼。

**Pinterest 的提醒：** 图片常常来源不明、被裁切或是概念稿，只适合找氛围和灵感，不能当作"真实产品是这样做的"证据。

**这个行业里以设计出名的品牌。** 搜"这个行业 + 品牌设计 / 官网改版"，看设计媒体和品牌评论（如 Brand New、It's Nice That、Dezeen）报道过谁；也看顶尖设计工作室的案例页，那里会写他们为什么这样做。

**行业龙头。** 设计不一定最好，但代表用户已经习惯的基线：结构、流程、该有的信息。

**不要用的来源：** 模板市场（Themeforest、各种建站模板）、"30 个最佳××网站"这类清单里没核实过的例子、只靠记忆的"我记得某某做得不错"。

### 怎么挑：一组 3 家

| 位置 | 作用 | 怎么选 |
| --- | --- | --- |
| 基线 | 用户已经习惯的结构和流程 | 行业龙头或最常见的成熟做法 |
| 天花板 | 这个品类能做到多好 | 设计媒体报道过、获过奖、设计师常提到的品牌，往往是小而精的 |
| 新鲜感 | 避免和同类长得一样 | 相邻品类里做得好的一家 |

每家都要过这几条：
- **任务和受众相同**，不只是同一个行业（卖咖啡豆订阅和开咖啡馆是两回事）。
- **够新：** 近两三年做过或改过版，页脚年份、内容日期可以作证。
- **真的有辨识度：** 把它的名字换成同类竞品，页面不成立。
- **亲眼看过还觉得好：** 打开截图后，如果自己看着也普通，就换掉，名气不算数。

### 参考库：越用越准

每次项目结束，把看过的参考和用户的反应记进仓库的参考库（例如 `library/<品类>.md`）：网址、截图路径、借了什么、用户说好还是不好、日期。下次遇到同一品类，先从参考库开始，再补新的。用户的品味会一次次沉淀下来，参考也会越选越准。网站会改版，超过一年的条目用之前重新截图确认。

### 拿不到时

agent 没有联网或打不开网站时，不要凭记忆描述网站长什么样。直接请用户发几张截图或链接，或在记录里写明"本次没有同类参考"。

### 截图和拆解

**拿到真实画面，不凭记忆。** 按上面挑出的 3 家打开截图（宽屏首屏，再往下一屏；有关键流程的再截一张关键控件或流程）。项目里有 `scripts/ref-shot.mjs` 可用。打不开就换一家；拿不到画面的，在记录里写明"未看到画面"。

注意抓对页面：品牌介绍页和产品本身的使用页往往完全不同（测试中曾把 grok.com 的聊天页当成了它的品牌官网）。

**每家拆 6–10 条看得见的要素，每条写两件事：它是什么样、为什么这样做。** 按这几层拆：首屏放了什么、主操作、信息顺序、关键控件、字体、颜色、图片怎么用、状态与反馈、文案语气。只拆出"干净、留白、一个强调色"说明没拆到位。

**分清三样东西：**

| | 是什么 | 怎么处理 |
| --- | --- | --- |
| 基线 | 用户已经习惯的结构：购物车在右上、结账三步、画廊作品先行 | 沿用，不让用户重新学 |
| 套路 | 这个品类人人都在用的默认样子 | 至少一个方向要打破 |
| 撞脸 | 字体、配色、主视觉、版式都和某一家一样 | 任何方向都不允许 |

同类参考给的是**地板**：用户的预期、行业的完成度、该有的信息和流程。它不负责让你与众不同，照着同类做只会和同类长得一样。

## 3. 找跨品类的氛围参考

表达和质感从品类外面找：用户的品味画像（`taste.md` 第 1 节）、用户给的参考、与这个题材气质相通的其他领域（电影、杂志、建筑、产品摄影）。只借它最有辨识度的一两个关系，例如"光从一个方向来，其余全暗"，不搬它的外观。

**两套参考要分开用：** 同类决定结构和流程，跨品类决定氛围和质感。测试中只用科技网站当参考，结果咖啡店也被拉成了科技外观。

## 4. 做成参考板，给用户指

把同类截图、跨品类参考，以及从中拆出的几种可能的氛围，并排放在一页上，每张附一句"借什么"。有人在时，把它和第 1 步的问题一起给用户，**这是第一个停下来的地方**：用户指出对的和不对的，再开始生图和做方向。

用户已经给了明确的参考和风格时，这一步可以简化成一句"我从这几家借这些"，不必停。

## 5. 留下记录

拆解参考时按这几个维度写，后面的 `DESIGN.md` 直接引用：配色、字体、留白、排版、组件、动效，再加上三个常被漏掉的：**主视觉与素材**（它用什么图、什么光）、**页面结构与叙事**（内容按什么顺序出现）、**状态与流程**（等待、出错、成功怎么处理）。

在项目目录写 `research.md`：问了什么、用户怎么答的、看了哪几家（附截图路径）、每家借什么不借什么、用户在参考板上的反应。后面的方向卡引用它，交付说明也引用它。
