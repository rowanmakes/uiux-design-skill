## 1. Nielsen 十大可用性启发式

笔记 03 里的六条是其中的子集。完整十条：

1. **系统状态可视性：** 操作后立即反馈。提交有加载态，成功有确认，不让人猜现在发生了什么。
2. **与真实世界相符：** 用用户熟悉的语言。"你的订单"，不是"交易实体记录"。
3. **用户掌控与自由：** 提供撤销和返回。填错能改，走错能退，不困死在流程里。
4. **一致性与标准：** 同功能同呈现。按钮长得一样，术语一致，用户不必重新学习。
5. **错误预防：** 比事后报错更好的是避免出错。日期用选择器，格式即时检查。
6. **辨识优于回忆：** 把选项直接展示出来，不逼用户记住上一页的内容。
7. **灵活与高效：** 给熟手快捷方式（快捷键、批量操作），不妨碍新手。
8. **美观与极简：** 每多一条无关信息，相关信息的可见度就降低一分。
9. **帮用户识别、诊断并从错误中恢复：** 错误信息用平实语言，说明问题并给出建设性出路。
10. **帮助与文档：** 最好不需要，需要时要易搜索、聚焦任务、步骤简短。

## 2. 设计定律与使用边界

| 定律 | 常见说法 | 正确用法与注意 |
| --- | --- | --- |
| 格式塔（接近、相似、封闭） | 让大脑自动归类元素 | 用间距和对齐分组，比加边框更轻 |
| 视觉层次 | 大小、粗细、颜色让重点浮出 | 一屏只让一个层级最强；全部强调等于没有强调 |
| Fitts 定律 | 目标越大越近越易点中 | 高频主操作放大并靠近手的位置；触控目标至少约 44px |
| Hick 定律 | 选项越多决策越慢 | 针对同等可能的选项。不等于"导航项越少越好"，分组、默认值、渐进展开同样有效 |
| Miller 定律 | 人脑一次处理 7±2 个单位 | 指短时记忆容量，不是菜单长度上限。用来支持"分块"，不要拿来给列表设硬性条数 |
| F 型阅读 | 用户 F 型扫描，重点放左上 | 在缺乏结构的文字密集页面上观察到的现象，更像结构不佳的后果。靠清晰标题、分块、前置关键词引导，不要为迎合 F 形而排版 |
| 80/20 | 80% 精力投到最重要的 20% | 用来排功能优先级，要有使用数据支撑，否则只是口号 |

这些是设计判断框架，不能替代用户研究。

## 3. 状态覆盖清单

只覆盖该流程实际需要的状态，不要为凑齐而造状态。

- 正常 / 空 / 加载 / 部分加载
- 错误（说明哪里失败 + 重试 / 修改 / 退出）
- 成功（确认实际完成的动作 + 后续入口）
- 取消与恢复（保留用户输入，重复点击处理）
- 对话框：焦点进入、Tab 范围、Escape 关闭、关闭后焦点返回、滚动恢复

## 4. 可访问性基础清单

- 键盘可完成所有主任务；焦点样式清楚可见
- 文字对比度：正文至少 4.5:1，大字与界面组件至少 3:1（WCAG AA）
- 控件有可访问名称；表单有关联的 label 和可理解的错误提示
- 不只靠颜色传达信息
- 动效尊重 `prefers-reduced-motion`
- 触控目标够大，间距够开
- 缩放到 200% 内容不丢失

检查要用实际操作，不是读代码就说通过。
