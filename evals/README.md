# 测试简报

`evals.json` 是固定简报，编号 1–4、6–8。编号 5 是留出简报，不参与调参，只在最后验证用一次。

## 现在怎么用

不再做"无技能 / 别的技能 / 我们"三组盲评打分：第一轮证明这种对照只能分出"还不错"和"还不错"，分不出惊艳。现在的做法：

- **实验：** 按 Skill 的 8 步跑，用户在第 5 步挑方向、最后评判"可以 / 不行 / 差在哪"。流程与提示词见 `../docs/playbook.md`。
- **回归：** Skill 有较大改动后，重跑 3 个固定简报（1 咖啡官网、7 工作台、一个用户真实项目），确认已达标的部分没被改坏。
- **消融：** 判断某个文件或步骤还要不要，见 `../docs/ablation-plan.md`。

每次运行都要有宽窄屏截图（标版本、页面、视口、状态）、`run-log.md`，以及 `design_lint.py` 和 `honesty_check.py` 的输出。

## 手机与桌面简报（6、7）

先用 HTML 原型测设计判断，这是最便宜的方式；设计定下来后再按实际技术栈实现，那是另一轮测试。

- 手机：截图视口 390×844，浅色、深色各一次；手势和转场必须实际点过、拖过。
- 桌面：常用尺寸 1280×800 和最小窗口尺寸各一次；菜单、快捷键、右键菜单按设计说明逐项核对。
