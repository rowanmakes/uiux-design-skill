## 2. 视频播放器实播与逐帧观察方法及局限说明（诚实声明）

### 观察方法
1. **Chromium 原生视频播放器加载与实播验证**：
   - 使用 Playwright Chromium 直接通过 `page.goto(pathToFileURL(webmPath).href)` 打开 `initial`、`round-2`、`final` 与 `reduced-motion` 共 8 个 `.webm` 视频文件。
   - 注：若在 `about:blank` 页面中通过 `<video src="file://...">` 挂载本地视频，Chromium 会因跨源安全策略阻止解码；直接导航至 `file://.../xxx-scroll.webm` 则由 Chromium 内置原生 `<video>` 播放器在同源上下文中完整解码播放（`readyState === 4`）。
   - 在原生播放器中执行 `video.play()` 并对关键时间点（`0.5s`、`4.0s`、`7.5s`、`11.5s`、`15.5s`、`19.5s`、`24.0s`）进行精确寻帧验证，同时截取带原生播放控件时间轴的播放器画面（见 `runs/e2-A-agy/recordings/final/frames/player-1440x900-t11.5s.png`，播放器控件显示 `0:11 / 0:26`）。
2. **连续时间轴序列图（Contact Sheet）与关键帧提取目视检查**：
   - 由于多模态模型视觉工具接收静态图像输入，无法像人眼盯住 60fps 屏幕一样直接接收实时视频流字节，为确保对整段约 26 秒视频的镜头推进、雾气漂移、窗光呼吸和跨幕转场做出 100% 诚实且高密度的视觉判断，我们结合了 **Chromium 播放器实播寻帧** 与 **FFmpeg 0.5fps（每 2.0 秒一帧，共 12 帧 `0.0s ~ 22.0s`）全片连续时间轴 Contact Sheet + 关键时间点高分原图提取**，并使用 `read_file` 逐张放大检视。

## 3. 三轮真实录屏迭代与问题修复记录

### 第一轮：`runs/e2-A-agy/recordings/initial/`
- **检查文件**：
  - 截图：`1440x900-01-start.png` ~ `04-end.png`，`390x844-01-start.png` ~ `04-end.png`
  - 视频与帧序列：`1440x900-scroll.webm`、`390x844-scroll.webm`、`frames/1440x900-contact-sheet.png`、`frames/390x844-contact-sheet.png`
- **目视发现的 5 项具体问题**：
  1. **光效圆盘硬边与窄屏遮挡**：`.light-source-window` 的径向渐变半径过小且不透明度偏高，在 `1440x900` 画面右侧形成可见的圆形光斑边界；在 `390x844-01-start.png` 中该光斑直接压在首屏主标题文字上方。
  2. **中西文混排标点字偶距异常**：`--font-serif` 中将西文字体 `'Georgia'` 排在 `'Noto Serif SC'` 之前，导致中文全角逗号 `，` 与句号 `。` 被 Georgia 窄标点接管，字距紧缩不自然。
  3. **场景章节面板仍有轻微“信息框/卡片感”**：`.scene-act` 的四周细边框与圆角、以及底部豆单 `.menu-row` 的四周边框，在视觉上仍有盒状卡片残留，不够彻底融入场景。
  4. **中点符号 `·` 残留**：舞台顶栏、镜头说明与豆单摘要中使用了 `·` 连接词，显得零碎。
  5. **窄屏（390×844）滚动进度与末屏高度错位**：由于窄屏下 `#subscribe-desk` 高度超过 `100vh`，导致 `390x844-03-two-thirds.png` 提前滑出故事第三幕，且 `390x844-04-end.png` 裁切了定制台上半部分标题。

### 第二轮：`runs/e2-A-agy/recordings/round-2/`
- **针对第一轮的修复措施**：
  1. 重写 `.light-source-window` 为大尺度非对称椭圆漫射光（`ellipse 62% 52% at 78% 60%`），彻底消除圆形硬边，并在移动端下移光源中心以避开文案区。
  2. 将 `--font-serif` 与 `--font-sans` 的中文字体（`'Noto Serif SC'`, `'Songti SC'`, `'PingFang SC'`, `'Microsoft YaHei'`）置于首位，中文全角标点恢复纯正的汉字排印呼吸感。
  3. 彻底移除 `.scene-act` 与 `.menu-row` 的四周封闭盒状边框与圆角，改为纯排版流 + 左侧单根琥珀细竖线（`border-left: 1px solid`）与水平发丝分隔线，真正实现「文字直接生长在场景暗部留白中」。
  4. 移除全页所有 `·` 连接符，改用排版留白或全角斜线 `／`。
  5. 统一宽窄屏的章节轨道高度比（`#top = 100vh`、`#narrative = 360vh`、`#subscribe-desk = 100vh`），使 `01-start`、`02-third`、`03-two-thirds`、`04-end` 在桌面与移动端均精准对应首屏、第二幕、第三幕与定制台全貌。
- **第二轮目视复查发现的新问题**：
  1. **移动端窄屏（390×844）存在 3 处单字成行（孤字）**：在 `390x844-02-third.png` 中出现 `奶油口 / 感`；在 `390x844-04-end.png` 中出现 `红茶尾 / 韵` 与 `双袋尝鲜组 / 合`。
  2. **第一幕（`story-01.webp`）定格时间偏短**：在 `round-2/frames/1440x900-contact-sheet.png` 中观察到 `t1to2` 从 `globalProgress = 0.21` 开始叠化，导致第一幕向第二幕过渡略早。

### 第三轮（终版）：`runs/e2-A-agy/recordings/final/`
- **针对第二轮的修复措施**：
  1. 为所有风味词组、产地名称、重量与价格单位添加 `<span class="nowrap">`（`white-space: nowrap`）不可拆分包裹，并在 `390x844` 下微调第三幕账页标签列宽（`84px`）与字号（`0.8125rem`）。
  2. 将第一幕向第二幕的转场区间由 `smoothstep(0.21, 0.30, globalProgress)` 延后并收紧至 `smoothstep(0.27, 0.32, globalProgress)`，让第一幕 `story-01.webp` 在 `t=3.5s ~ 8.0s` 期间拥有充裕的 100% 满不透明度展示时长，同时确保 `globalProgress = 0.333`（`02-third`）时已 100% 定格在第二幕 `story-02.webp`。
- **第三轮终版目视验证结果**：
  - `1440x900-01-start.png` ~ `04-end.png` 与 `390x844-01-start.png` ~ `04-end.png` 共 8 张截图，以及 `frames/1440x900-contact-sheet.png`、`frames/390x844-contact-sheet.png`、`frames/1440x900-t07.5s-act1.png`、`frames/390x844-t07.5s-act1.png` 全部通过目视检查：零孤字、零重叠、零裁切、零控制台或网络错误。

## 5. 六项审美与品质自检清单（6-Point Taste Checklist）

1. **拿掉品牌名之后，这个页面靠什么被记住？**
   - 靠「从破晓前的成都半山雾海，顺着山脊推近林间微亮暖窗，最终停在烘焙间厚木桌与热咖啡旁」的连续电影推镜体验，以及克制沉静的冷黛山雾（`250°`）与暖琥珀炉火（`66°`）冷暖光影对撞。
2. **主视觉是不是一个完整的场景，而不是拼出来的组件墙？**
   - 是。首屏与三幕叙事均以全出血高完成度场景画面（`hero-01.webp` 及 `story-01~03.webp`）为空间主体，没有任何悬浮小卡片墙、渐变圆球或跑马灯。
3. **文案、字体、留白是不是在帮画面说话，而不是盖住画面？**
   - 是。所有排版均严格锚定在画面左侧 1/3 的深色山林与室内暗部留白区，右侧完全让位给雾海、木屋暖窗、200g 牛皮纸豆袋与冒热气的陶杯；以宋/明体衬线标题配无衬线内文与等宽表格数字，不加任何封闭卡片边框。
4. **滚动时，用户是在推进一段体验，还是只是把一块块内容往下拉？**
   - 是在推进一段连续的空间镜头：`window.scrollY` 实时驱动三张叙事画面的景深缩放、叠化与窗光/水汽强度变化，引导视线从山谷远眺自然步入木屋窗前。

   - 是。云雾（`44s` / `54s`）、杯口水汽（`38s`）、暖窗呼吸（`8s`）与零星微尘（`8.6s~13.8s`）均采用长周期低振幅的非对称缓动，没有任何弹窗跳动、数字乱滚或生硬闪烁。
6. **页面上有没有任何「为了显得像官网」而硬塞的假信息或多余模块？**
   - 没有任何虚构评价、假媒体背书、假销量计数器或倒计时弹窗。全页严格只呈现固定的品牌介绍、三款当期咖啡豆与订阅规则，且样例与生成图说明仅在页脚 `.site-footer` 诚实出现一次。
